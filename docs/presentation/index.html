Act I · find
FindBuildProve

Passions are built, not found.

We don't ask a child what they love. We manufacture interest through varied exposure, then watch what they come back to on their own.

The morning runs on earned progress. In the afternoon we keep the discovery signal reward-neutral on purpose, so we're measuring genuine return, not who's chasing the prize.

What a child says they like predicts what they do only modestly. Self-report ↔ behavior · rule of thumb
The trustworthy signal is unprompted return once novelty and prompting fade. Hidi–Renninger four-phase interest model · 2006
ANTICIPATE JOE HERE. He's pro-extrinsic-reward, so he'll push on "reward-neutral." Have this ready: we're not anti-reward. Rewards are the right tool in the MORNING, where the target behavior is defined (master the content): pay for throughput, get throughput. The afternoon DISCOVERY signal is a different job: we're detecting what a child returns to WITHOUT being asked. Attach a reward to exploration and two things break. (1) Every kid does it, so the signal is worthless: you measure prize-chasing, not genuine interest. (2) For the kids who DID have intrinsic interest, an expected tangible reward can crowd it out (overjustification / reward-undermining: Deci, Koestner & Ryan 1999 meta-analysis, expected tangible rewards reduce free-choice intrinsic motivation, ~d = -.28 to -.40). So for THIS group of open-ended extracurriculars, extrinsic motivation doesn't help: it manufactures false positives and can dampen the very interest we're hunting for. RECONCILE so it doesn't sound anti-reward: reward-neutrality is ONLY the discovery measurement window. Once a spike is certified and the child enters the Build ascent (S6), earned progress and rewards come back. Phase-specific, not a philosophy against rewards. Two supporting figures, stated honestly. Self-report predicts behavior only "modestly" (~0.4 rule of thumb, NOT a precise landmark r; I previously had a wrong number). Hidi–Renninger (2006, Educational Psychologist 41(2)): four interest phases; the 2→3 crossing is when re-engagement becomes self-generated rather than externally supported (support isn't "absent", it's "no longer required").

Act II · evidencegraph

A finished artifact can't tell you who made it.

An essay, a painting, a repo: the result is silent on whether it was the child, an AI, a parent, a tutor, or paid help.

The reflex is to catch it after the fact, scanning the work to flag what "looks like AI." That doesn't just fail; it punishes the wrong children.

AI detectors false-flag non-native English writers: ~61% of TOEFL essays were wrongly called AI in a Stanford study. So we never run one against a person. Liang et al., Patterns, 2023 (n≈91)

The other reflex, trusting a version history, only looks like proof: timestamps and authorship are typed in, and can be rewritten or back-dated. A claim, not evidence.

Felipe leads from here. Two dead-end reflexes before our approach. (1) Detect the person: scan and flag AI. Liang et al. 2023 (Patterns, Stanford): 7 detectors flagged non-native TOEFL essays as AI at ~61.3% avg false-positive, near-perfect on US 8th-grade essays; small sample (n≈91). Vanderbilt disabled Turnitin's detector citing this bias. That's the transition into the chip: the fix punishes the wrong kids. (2) Trust the version history: it's typed-in and rewritable, so it's a claim, not evidence. The problem is also BROADER than AI: parent/tutor/paid help all count. Both reflexes fail, so S10 = record the making instead.
Act II · the idea

Record the journey, not the result.

One tamper-evident, content-addressed record per project: append-only, with a fingerprint that changes if a single byte changes.

All help is recorded openly. Declared help (AI, parent, mentor) is neutral. Only hidden help, passed off as solo, is the problem.

The reframe: don't detect, record. Content-addressed means the fingerprint IS the content, so tampering is self-evident. Stress the help policy: this is what makes it fair and un-gameable. Declared help is fine, only concealment is the failure. Keep crypto depth for Q&A (backup slides).

Backup · q&a

How the proof holds.

Every step is content-addressed: its id is a SHA-256 digest of its own bytes, so any later edit changes the id and breaks the chain.

The whole graph rolls up to one Merkle root a verifier can recompute, and it's designed so only that root, never the content, is anchored externally.

For "how do you know it wasn't tampered with?" Content-addressing: the id IS the hash of the content (real SHA-256), so a changed byte changes the id. The whole graph rolls up to an RFC-6962 Merkle root (ordered by timestamp then id, so it's reproducible) that an outside verifier recomputes. Today "verify" means integrity of this copy; external anchoring (a Sigstore/Rekor-class transparency log) and signing are on the roadmap. Answer the mechanism; don't volunteer deployment status.

Backup · q&a

Architecture

A standalone Rust service: a pure engine (content-addressing, Merkle roots, human-authority validation) behind storage ports, with a thin read-only UI that never recomputes trust.

It's its own repo, not a module of PassionLab: a Rust workspace (engine / ports / store / service) with a JS read-only viewer. The engine owns every byte that ever gets hashed; the UI only displays roots and proofs, so it can't fake a verdict. PassionLab hands projects to it over the same HTTP API a connector would use. Any human judgment (an Outcome or grade) requires a named human actor; a model actor may only appear on declared Assistance or Review.
